# 要件定義書

## プロジェクト概要

| 項目 | 内容 |
|------|------|
| プロジェクト名 | クロス麻雀部オンライン |
| プラットフォーム | Discord Bot |
| 目的 | 麻雀部メンバーの定時マッチング・対戦管理・成績記録の自動化 |
| 作成日 | 2026-03-31 |
| ステータス | ドラフト |

---

## 1. 業務要件

### 1.1 背景・目的
- 麻雀部の定時開催（毎日0時〜）における参加者募集・マッチング・成績管理を自動化する
- 手動での人数確認・部屋割り・成績記録の負担を解消する

### 1.2 対象ユーザー
- クロス麻雀部のDiscordサーバーメンバー

### 1.3 運用スケジュール
- **Phase 1（初期）**: 毎日 0:00〜 開催
- **Phase 2（将来）**: 開催時間の増設

---

## 2. 機能要件

### F-01: 参加受付機能
- 開催時間にBot が参加募集メッセージを投稿する
- メンバーはボタン押下で参加意思を表明する（匿名投票形式）
- 3人戦 / 4人戦 を選択して参加登録できる
- 参加取消も可能とする

### F-02: 待機状況リアルタイム表示
- 3人戦の待ち人数をリアルタイム表示する
- 4人戦の待ち人数をリアルタイム表示する
- 参加・取消に応じて即座に更新される

### F-03: マッチング機能
- 3人戦と4人戦の同時エントリーを可能とする
- **4人戦を優先**：同時エントリー者は4人戦が先に成立した場合そちらに割り当てる
- 3人戦：3人集まり次第、待機者からランダムに3人を抽出する
- 4人戦：4人集まり次第、待機者からランダムに4人を抽出する
- マッチング成立時、参加者全員に通知する

### F-04: 対戦グループ管理
- マッチング成立後、対戦グループ用のテキストチャンネルまたはスレッドを自動作成する
- 部屋番号などの対戦情報を共有する場を提供する
- ボイスチャンネルへの自動招待（可能であれば）

### F-05: 欠席・辞退・解散処理
- マッチング成立後に欠席・辞退が発生した場合、当該メンバーをグループから退席させる
- 辞退発生時、待機キューに補充可能な人がいれば自動補充する
- 補充不可の場合はグループを解散する
- メンバーがBotに「グループ解散」を報告できる
- 解散報告後、グループを解体し待機キューの状態を更新する

### F-06: 成績記録機能（画像認識）
- ゲーム終了後、対戦結果のスクリーンショットをDiscordに送信する
- Bot が画像を解析し、以下の情報を認識・記録する：
  - 順位（1位〜3位 or 4位）
  - 得点
  - 順位ウマ（順位点）
- 認識結果を確認メッセージとして表示し、修正可能とする
- **画像認識失敗時は手動入力にフォールバックする**

### F-07: 成績データベース
- 対戦ごとの結果をデータベースに保存する
- メンバーごとの累計成績を管理する

### F-08: ランキング・統計機能
- メンバーごとの成績ランキングを表示する（総合得点、平均順位 等）
- 対戦数、勝率、連対率などの統計情報を閲覧できる
- 期間指定でのランキング表示（月間、通算 等）

---

## 3. 非機能要件

### NF-01: 可用性
- 毎日0時の開催時間にBot が確実に稼働していること
- Bot のダウンタイムは最小限とする

### NF-02: 応答性能
- ボタン押下〜待機人数更新：2秒以内
- マッチング成立〜通知：5秒以内

### NF-03: データ永続性
- 成績データは永続的に保存する
- データベースのバックアップを定期的に実施する

### NF-04: セキュリティ
- 参加投票は他メンバーから見えない（匿名性）
- Botトークン等の認証情報は安全に管理する

### NF-05: 拡張性
- 開催時間の増設に対応できる設計とする
- 将来的な機能追加（ランキング表示、統計機能等）を見据える
