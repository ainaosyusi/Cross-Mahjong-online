### 1.3 cogs/matching.py — 参加受付・マッチング

**責務**: F-01（参加受付）、F-02（待機表示）、F-03（マッチング）

#### クラス設計

```
class MatchingCog(commands.Cog):
    - bot: commands.Bot
    - queue: QueueService          # services/queue.py のインスタンス
    - recruitment_message_id: int  # 現在の募集メッセージID

    async def start_recruitment()      # 募集メッセージ投稿
    async def stop_recruitment()       # 募集停止
    async def on_join_button(interaction, match_type)  # 参加ボタン処理
    async def on_cancel_button(interaction)            # 取消ボタン処理
    async def update_queue_display()   # 待機人数の表示更新
    async def try_match()              # マッチング判定・実行
```

#### メソッド詳細

**start_recruitment()**
```
トリガー: スケジューラ（毎日0:00）or /start_matching コマンド
処理:
  1. 待機キューを初期化（queue.clear()）
  2. 募集 Embed + ボタン View を作成
  3. #麻雀マッチング に送信
  4. recruitment_message_id を保存
```

**on_join_button(interaction, match_type)**
```
トリガー: [4人戦に参加] / [3人戦に参加] / [両方に参加] ボタン
処理:
  1. interaction.user.id を取得
  2. 既にキューに入っている場合 → ephemeral で「既に参加済みです」
  3. queue.add(user_id, match_type) を呼び出し
     - match_type: "4", "3", "both"
  4. members テーブルに未登録なら自動登録（upsert）
  5. update_queue_display() を呼び出し
  6. try_match() を呼び出し
  7. ephemeral で「参加登録しました」を返す
```

**try_match()**
```
処理（4人戦優先）:
  1. queue_4 = queue.get_queue(MATCH_TYPE_4)  # 4人戦のみ + 両方
  2. if len(queue_4) >= 4:
       selected = random.sample(queue_4, 4)
       queue.remove_users(selected)
       await create_match_group(selected, MATCH_TYPE_4)
       await try_match()  # 残りで再チェック（再帰）
       return
  3. queue_3 = queue.get_queue(MATCH_TYPE_3)  # 3人戦のみ + 両方（4人戦に選ばれなかった人）
  4. if len(queue_3) >= 3:
       selected = random.sample(queue_3, 3)
       queue.remove_users(selected)
       await create_match_group(selected, MATCH_TYPE_3)
       await try_match()  # 残りで再チェック（再帰）
```

**update_queue_display()**
```
処理:
  1. queue から 4人戦待ち人数、3人戦待ち人数を取得
  2. 募集メッセージの Embed を編集
     - recruitment_message_id を使って message.edit()
```

### 1.4 cogs/group.py — 対戦グループ管理

**責務**: F-04（グループ管理）、F-05（辞退・解散）

#### クラス設計

```
class GroupCog(commands.Cog):
    - bot: commands.Bot
    - active_matches: dict[int, MatchInfo]  # match_id → MatchInfo

    async def create_match_group(users, match_type)  # グループ作成
    async def on_withdraw_button(interaction)         # 辞退処理
    async def on_disband_button(interaction)          # 解散処理
    async def disband_command(ctx)                    # /disband コマンド
```

#### データ構造

```python
@dataclass
class MatchInfo:
    match_id: int           # DB上の対戦ID
    match_type: int         # 3 or 4
    thread_id: int          # スレッドID
    voice_channel_id: int   # ボイスチャンネルID
    player_ids: list[int]   # 参加者のDiscord ID
```

#### メソッド詳細

**create_match_group(users, match_type)**
```
処理:
  1. DB: matches テーブルに INSERT (status='playing')
  2. DB: match_players テーブルに参加者を INSERT
  3. #麻雀マッチング 内にスレッド作成
     - thread = await channel.create_thread(name=f"対戦卓-{match_id:03d}")
  4. カテゴリ内にボイスチャンネル作成
     - vc = await guild.create_voice_channel(name=f"対戦卓-{match_id:03d}")
  5. スレッドにマッチング成立メッセージ送信（メンバーメンション）
  6. 各メンバーにボイスチャンネルへの招待リンクを送信
  7. active_matches に登録
  8. 募集メッセージの待機人数を更新
```

**on_withdraw_button(interaction)**
```
トリガー: [辞退する] ボタン
処理:
  1. interaction.user.id からどの match に属するか特定
  2. player_ids から当該ユーザーを除去
  3. DB: match_players から DELETE
  4. 待機キューから同種別の待機者を検索
  5. if 補充可能:
       補充者を選択、match_players に INSERT
       スレッドに「@辞退者 が辞退 → @補充者 が参加」通知
       補充者をキューから除去
       募集メッセージの待機人数を更新
  6. else:
       await disband_match(match_id)
```

**disband_match(match_id)**
```
処理:
  1. DB: matches.status = 'disbanded', finished_at = now
  2. スレッドに解散メッセージ送信
  3. スレッドをアーカイブ
  4. ボイスチャンネルを削除
  5. active_matches から削除
  6. 残メンバーに「キューに戻りますか？」ボタン付きメッセージ送信
```

### 1.5 cogs/result.py — 成績記録

**責務**: F-06（画像認識・手動入力）、F-07（DB保存）

#### クラス設計

```
class ResultCog(commands.Cog):
    - bot: commands.Bot
    - ocr_service: OCRService      # services/ocr.py のインスタンス
    - pending_results: dict[int, ResultData]  # message_id → 認識結果

    async def on_message(message)              # 画像受信検知
    async def on_confirm_button(interaction)    # 確定ボタン
    async def on_edit_button(interaction)       # 修正ボタン
    async def result_command(ctx, ...)          # /result 手動入力
```

#### データ構造

```python
@dataclass
class ResultData:
    match_id: int | None           # 紐づく対戦ID（特定できた場合）
    players: list[PlayerResult]    # 各プレイヤーの結果

@dataclass
class PlayerResult:
    discord_id: int    # Discord ユーザーID
    rank: int          # 順位 (1-4)
    score: int         # 素点 (例: 45000)
    point: float       # ポイント (例: +45.0)
```

#### メソッド詳細

**on_message(message)**
```
トリガー: #対戦結果 チャンネルへの画像付きメッセージ
処理:
  1. message.channel.id が RESULT_CHANNEL_ID でなければ無視
  2. message.attachments が空なら無視
  3. 画像をダウンロード → bytes
  4. result = ocr_service.recognize(image_bytes)
  5. if result is None:
       「認識失敗」メッセージ + /result コマンド案内を送信
       return
  6. 認識結果の Embed を作成（順位・スコア一覧）
  7. [確定] [修正する] ボタン付きで送信
  8. pending_results[msg.id] = result
```

**on_confirm_button(interaction)**
```
処理:
  1. result = pending_results.get(interaction.message.id)
  2. DB: match_results テーブルに INSERT（各プレイヤー分）
  3. DB: matches.status = 'finished', finished_at = now
  4. 「結果を記録しました」メッセージ
  5. pending_results から削除
```

**result_command(ctx, ...)**
```
書式: /result @user1 1 45000 @user2 2 32000 @user3 3 22000 @user4 4 11000
処理:
  1. 引数をパース: [(user, rank, score), ...]
  2. ポイント（ウマ込み）を計算
  3. 確認 Embed を表示 + [確定] [修正する]
  4. 確定時に DB 保存
```

### 2.1 services/queue.py — 待機キュー管理

**責務**: メモリ上の待機キュー操作

```python
class QueueService:
    _queue_4: set[int]     # 4人戦のみエントリーしたユーザーID
    _queue_3: set[int]     # 3人戦のみエントリーしたユーザーID
    _queue_both: set[int]  # 両方エントリーしたユーザーID

    def add(user_id: int, entry_type: str) -> bool
        """
        entry_type: "4" | "3" | "both"
        既にいずれかのキューに存在する場合は上書き
        """

    def remove(user_id: int) -> None
        """全キューから削除"""

    def remove_users(user_ids: list[int]) -> None
        """複数ユーザーを全キューから削除"""

    def get_queue_4(self) -> list[int]
        """4人戦のマッチング対象 = _queue_4 ∪ _queue_both"""

    def get_queue_3(self) -> list[int]
        """3人戦のマッチング対象 = _queue_3 ∪ (_queue_both - 4人戦で選ばれた人)"""

    def count_4(self) -> int
        """4人戦待ち人数"""

    def count_3(self) -> int
        """3人戦待ち人数"""

    def clear(self) -> None
        """全キューをクリア"""
```

**キュー管理の状態遷移図**:
```
ユーザーA が [両方に参加] を押下
    │
    ▼
_queue_both = {A}

4人戦成立（A, B, C, D が選ばれる）
    │
    ▼
_queue_both から A を削除
_queue_4 から B, C, D を削除

残った _queue_both のメンバーは
3人戦のマッチング判定に含まれる
```

### 2.2 services/ocr.py — 画像認識

**責務**: 雀魂の結果画面を認識し、順位・スコアを抽出

```python
class OCRService:
    def recognize(image_bytes: bytes) -> ResultData | None
        """
        画像を解析し、対戦結果を返す。
        認識失敗時は None を返す。
        """

    def _preprocess(image: np.ndarray) -> np.ndarray
        """画像前処理（リサイズ、グレースケール、二値化）"""

    def _detect_result_area(image: np.ndarray) -> np.ndarray | None
        """結果画面領域の検出（テンプレートマッチング）"""

    def _extract_rows(result_area: np.ndarray) -> list[np.ndarray]
        """各プレイヤー行の切り出し"""

    def _read_rank(row: np.ndarray) -> int
        """順位の読み取り（1〜4）"""

    def _read_player_name(row: np.ndarray) -> str
        """プレイヤー名の読み取り"""
```

**画像認識パイプライン**:
```
入力画像 (スクリーンショット)
    │
    ▼
1. 前処理
   - BGR → グレースケール変換
   - リサイズ（幅1280px基準に正規化）
   - ガウシアンブラー（ノイズ除去）
    │
    ▼
2. 結果画面検出
   - 雀魂の結果画面テンプレートとマッチング
   - マッチスコアが閾値以下 → None（認識失敗）
    │
    ▼
3. 行分割
   - 結果領域を水平方向に分割
   - 各プレイヤーの行を取得（3行 or 4行）
    │
    ▼
4. 各行から情報抽出（Phase 1: 最小構成）
   - 順位エリア → OCR → int
   - プレイヤー名エリア → OCR → str
    │
    ▼
出力: ResultData（順位 + プレイヤー名）
```

**ポイント計算について**:
```
雀魂の結果画面にはウマ込みの最終ポイントが表示されるため、
Bot側でのポイント計算は不要。画面の数値をそのまま記録する。
```

**Phase 1 で認識する情報（最小構成）**:
- 順位（1〜4位）
- プレイヤー名
- ※ スコア・ポイントは Phase 2 以降で対応可能

```python
        year: int = None,

    ) -> list[RankingEntry]

        SQLクエリで集計。
        """

        discord_id: int,
        period: str = "all"
    ) -> PlayerStats
        """
        個人の統計情報を返す。
        """
```

**ランキング集計SQL**:
```sql
SELECT
    m.discord_id,
    m.display_name,
    COUNT(*) AS game_count,
    ROUND(AVG(r.rank), 2) AS avg_rank,
    ROUND(SUM(r.point), 1) AS total_point,
    ROUND(SUM(CASE WHEN r.rank = 1 THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 1) AS top_rate,
    ROUND(SUM(CASE WHEN r.rank <= 2 THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 1) AS rentai_rate
FROM match_results r
JOIN members m ON m.id = r.member_id
JOIN matches mt ON mt.id = r.match_id
WHERE mt.status = 'finished'
  AND mt.finished_at >= :start_date
  AND mt.finished_at < :end_date
GROUP BY m.id
ORDER BY total_point DESC;
```

```python
import aiosqlite

_db: aiosqlite.Connection | None = None

async def init(db_path: str):
    """DB接続を開き、テーブルを作成する"""
    global _db
    _db = await aiosqlite.connect(db_path)
    _db.row_factory = aiosqlite.Row
    await _db.execute("PRAGMA journal_mode=WAL")  # 書き込み性能向上
    await _db.execute("PRAGMA foreign_keys=ON")
    await create_tables()

async def get_db() -> aiosqlite.Connection:
    """DB接続を返す"""
    return _db

async def close():
    """DB接続を閉じる"""
    if _db:
        await _db.close()
```

### 3.2 database/models.py — テーブル作成SQL

```sql
CREATE TABLE IF NOT EXISTS members (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    discord_id    TEXT    UNIQUE NOT NULL,
    display_name  TEXT    NOT NULL,
    created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS matches (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    match_type       INTEGER NOT NULL,
    status           TEXT    NOT NULL DEFAULT 'waiting',
    thread_id        TEXT,
    voice_channel_id TEXT,
    created_at       DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    finished_at      DATETIME
);

CREATE TABLE IF NOT EXISTS match_players (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    match_id   INTEGER NOT NULL REFERENCES matches(id),
    member_id  INTEGER NOT NULL REFERENCES members(id),
    joined_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(match_id, member_id)
);

CREATE TABLE IF NOT EXISTS match_results (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    match_id   INTEGER NOT NULL REFERENCES matches(id),
    member_id  INTEGER NOT NULL REFERENCES members(id),
    rank       INTEGER NOT NULL,
    score      INTEGER NOT NULL,
    point      REAL    NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(match_id, member_id)
);

-- インデックス
CREATE INDEX IF NOT EXISTS idx_members_discord_id ON members(discord_id);
CREATE INDEX IF NOT EXISTS idx_matches_status ON matches(status);
CREATE INDEX IF NOT EXISTS idx_matches_created_at ON matches(created_at);
CREATE INDEX IF NOT EXISTS idx_match_results_member_id ON match_results(member_id);
CREATE INDEX IF NOT EXISTS idx_match_results_member_date ON match_results(member_id, created_at);
```

## 5. エラーハンドリング設計

### 5.1 エラー分類と対応

| エラー種別 | 例 | 対応 |
|-----------|-----|------|
| ユーザー操作エラー | 二重参加、不正なコマンド引数 | ephemeral メッセージで案内 |
| Discord API エラー | レート制限、チャンネル作成失敗 | リトライ（最大3回、指数バックオフ） |
| 画像認識エラー | OCR失敗、テンプレート不一致 | 手動入力へフォールバック |
| DB エラー | 書き込み失敗、制約違反 | ログ出力 + ユーザーに「エラーが発生しました」通知 |
| Bot クラッシュ | 未ハンドル例外 | systemd による自動再起動 |

### 5.2 ログ設計

```
ログレベル:
  DEBUG   - キュー操作詳細、DB クエリ
  INFO    - マッチング成立、成績記録、ユーザー参加/離脱
  WARNING - OCR 認識失敗、API リトライ
  ERROR   - DB エラー、予期しない例外

ログ出力先:
  stdout → journalctl で確認（systemd 経由）

ログフォーマット:
  [2026-03-31 00:05:12] INFO  matching: マッチング成立 match_id=42 type=4 players=[UserA,UserB,UserC,UserD]
```
